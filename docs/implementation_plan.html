Kế Hoạch Triển Khai v2 - Khắc Phục 5 Vấn Đề Kỹ Thuật

Bản sửa đổi kế hoạch dựa trên 5 phản hồi kỹ thuật về HMAC Contract, QR Code local, Polling Cleanup, Memory Cleanup, và Data thật trên Fake Gateway UI.

QUAN TRỌNG:

Mọi chỉnh sửa chỉ giới hạn trong phạm vi 5 vấn đề dưới đây. Không thay đổi hoặc chỉnh sửa bất kỳ nghiệp vụ nào khác ngoài phạm vi này.

Vấn đề 1: Thống nhất HMAC Signature Contract

Thống nhất cơ chế ký HMAC SHA256 cho Callback IPN từ Fake Gateway về Main Backend:

  • Payload ký & gửi đi: { paymentRequestId, bookingId, status, resolvedAt } (Thứ tự key được sắp xếp cố định).
  • Thuộc tính Status: Nhận giá trị success hoặc failed (chữ thường).
  • Header chứa chữ ký: X-Gateway-Signature: <signature>.
  • Xác thực phía Main Backend: Sử dụng crypto.timingSafeEqual để chống timing attack.
  • Biến môi trường dùng chung: CALLBACK_SIGNATURE_SECRET ở cả 2 phía.

Cần cập nhật các file:

  • fake-payment-gateway/backend/src/services/callback.service.js (Ký và gửi callback với header và body mới).
  • backend/src/validations/payment.validation.js (Sửa callbackSchema để chỉ validate 4 trường mới trong body).
  • backend/src/controllers/payment.controller.js (Lấy signature từ headers x-gateway-signature truyền vào service).
  • backend/src/services/payment.service.js (Xác thực chữ ký timingSafeEqual, đơn giản hóa finalizeSuccessfulPayment và finalizeUnsuccessfulPayment để không check các trường cũ).

Vấn đề 2: QR Code bằng Thư viện Local

Loại bỏ hoàn toàn việc gọi API online từ qrserver.com vì nguy cơ lỗi khi không có mạng/CI.

  • Cài đặt các thư viện: react-native-qrcode-svg và react-native-svg trong Expo app.
  • Cập nhật file mobile-app/app/(user)/booking/checkout.tsx để import component QRCode từ react-native-qrcode-svg và hiển thị mã QR trực tiếp tại local.

Vấn đề 3: Polling & Countdown Cleanup trên Mobile App

Tránh memory leak và lỗi cập nhật state trên unmounted component bằng cách thêm cleanup triệt để:

  • Cập nhật checkout.tsx để thực hiện clear interval khi unmount hoặc khi trạng thái chuyển sang trạng thái cuối cùng (success/failed/expired/cancelled).
  • Tách biệt polling trạng thái và countdown timer thành 2 hook useEffect riêng biệt để quản lý cleanup rõ ràng.

Vấn đề 4: Tự Động Dọn Dẹp Bộ Nhớ (Memory Cleanup) trên Fake Gateway

Tránh tràn RAM khi Fake Gateway chạy trong thời gian dài bằng cơ chế dọn dẹp định kỳ:

  • Thêm hàm dọn dẹp vào cuối file fake-payment-gateway/backend/src/configs/memoryDb.js.
  • Chạy setInterval định kỳ mỗi 10 phút, xóa toàn bộ giao dịch hết hạn hoặc cũ hơn 1 giờ (60 phút).

Vấn đề 5: Hiển Thị Dữ Liệu Thật trên Fake Gateway UI

Loại bỏ hoàn toàn cơ chế sinh ngẫu nhiên thông tin chi tiết đặt vé. Sử dụng dữ liệu thật được truyền sang từ Backend chính:

  • Main Backend (payment.service.js): Khi gọi tạo session sang Fake Gateway, tự động .populate() thông tin User, Movie, Room từ Booking để lấy các trường: userName, movieTitle, showtimeAt, roomName, seats gửi sang Fake Gateway.
  • Fake Gateway Backend (gatewayPayment.service.js): Chỉ nhận dữ liệu từ request body và lưu trực tiếp vào Map in-memory, không tự sinh ngẫu nhiên.
  • Fake Gateway UI: Hiển thị trực tiếp dữ liệu thật. Sửa App.jsx và các component liên quan để ánh xạ chính xác thông tin thật này.

3. Kế Hoạch Xác Minh (Verification Plan)

  • Verify HMAC: Bấm Approve trên Gateway UI → Quan sát logs callback thành công 200 trên backend chính, đảm bảo không gặp lỗi signature 401.
  • Verify QR Code: Chạy mobile app trên môi trường giả lập (hoặc tắt internet giả lập) để xem QR có hiển thị ngay lập tức từ thư viện local hay không.
  • Verify Cleanup: Điều hướng qua lại giữa màn hình checkout và màn hình chọn ghế nhiều lần, kiểm tra xem có xuất hiện lỗi log memory leak hay không.
  • Verify UI Data: Đặt vé với phim "Dune: Part Two", ghế "D5, D6" → Mở VeriPay Admin kiểm tra xem UI có hiển thị đúng phim "Dune: Part Two" và ghế "D5, D6" hay không.
