Tóm tắt điều đã làm được trong codebase

Backend

  • User model đã dùng fullName, phoneNumber, avatarUrl, passwordHash; không định nghĩa name, phone, avatar, password như field User.
  • Auth service nhận mật khẩu plaintext ở request, hash bằng bcrypt và chỉ lưu vào passwordHash.
  • Joi validation dùng strict object, chặn field không khai báo trong register, login, update profile và change password.
  • Response mapper sanitizeUser chỉ trả canonical profile fields và không expose passwordHash.
  • Booking và Ticket populate user bằng fullName email phoneNumber avatarUrl role.
  • Seed user đã chuyển sang schema mới, avatar seed trỏ tới avatarUrl.

Admin web và Mobile app

  • Admin type chính đã có User.fullName, phoneNumber, avatarUrl.
  • Admin profile form gửi fullName, phoneNumber, avatarUrl lên backend.
  • Admin Users, Bookings, Tickets hiển thị user bằng fullName và phoneNumber.
  • Mobile API client và app store normalize user bằng canonical fields.
  • Mobile profile, edit profile và change password screen đã gửi confirmPassword và dùng fullName, phoneNumber, avatarUrl.
  • Schema user/profile mới được xác nhận bằng kiểm tra trực tiếp trong quá trình dọn dẹp. Các test tạm sinh ra cho audit đã được loại bỏ khỏi project runtime.

Đề xuất cải tiến

Ưu tiên gần

  • Giữ plan/report cũ ở trạng thái archived để tránh nhầm với nguồn triển khai hiện tại.
  • Dùng schema user/profile mới duy nhất trong auth, profile, booking, ticket, admin web và mobile app.
  • Dùng multipart key avatarFile; response và DB vẫn dùng avatarUrl.
  • Giữ test validation reject payload có name, phone, avatar trong register/profile update.

Ưu tiên sau

  • Đưa test schema user/profile vào script chuẩn, ví dụ npm run test:user-profile ở backend.
  • Tạo contract type dùng chung hoặc snapshot response mẫu cho auth, booking và ticket.
  • Nếu database local/dev còn dữ liệu cũ và muốn bỏ toàn bộ dữ liệu đó, dừng backend, drop database thủ công bằng mongosh, rồi chạy lại seed schema mới. Không chạy thao tác này trên production khi chưa backup.
  • Thêm CI chạy backend schema tests, admin build và mobile lint để chặn regression.
Lưu ý vận hành:

Không nên chạy reset/drop database tự động trong app startup, backend script hoặc seed runtime. Nếu cần reset môi trường local/dev, làm thủ công theo README backend và xác nhận đúng database trước khi drop.
